# Atlas AI v1.0.0

Primera versión completa: subir documentos y preguntarles con **respuestas citadas y abstención cuando no hay
evidencia**, ejecutable en local con un comando. Esta nota resume qué incluye, qué se midió, qué cuesta y qué se decidió
a cambio de qué. Léela con el apartado de [limitaciones](#limitaciones): varias cifras proceden de modelos falsos.

## Qué incluye

- **Aplicación**: portada, registro y acceso, biblioteca de documentos con estados en vivo (`UPLOADED → PROCESSING →
  READY | FAILED`), y preguntas con respuesta, fuentes desplegables con el pasaje original y abstención explicada.
  Modo claro y oscuro, y adaptada a móvil.
- **Pipeline RAG**: extracción de texto (PDF, TXT, Markdown), fragmentado con solape, embeddings, búsqueda por coseno con
  índice HNSW en pgvector, reranking léxico opcional, contexto acotado, generación con verificación de citas.
- **Seguridad**: aislamiento por usuario en toda la tubería, sesiones en servidor con cookie `HttpOnly` y CSRF,
  límites de archivo (20 MB, 500 páginas, 5 M de caracteres, 60 s), cuotas diarias por usuario, texto recuperado tratado
  como no confiable y registro que puede cerrarse (`REGISTRATION_ENABLED=false`).
- **Operación**: Docker Compose con base de datos, migraciones, API, worker y frontend; pruebas de humo
  (`python -m app.smoke`); copias de seguridad, restauración y reconciliación (`scripts/backup.sh`,
  `scripts/restore.sh`, `python -m app.reconcile`); CI para backend y frontend.
- **Evaluación**: dataset versionado de 32 preguntas sobre 6 documentos, métricas de recuperación y de respuesta,
  comparación de configuraciones y una puerta de regresión de 10 umbrales.

## Métricas

> **Todas se midieron con proveedores `fake`** (embeddings por hashing y un respondedor extractivo), con el dataset
> `atlas-qa@1.1.0`. **No dicen cuánto acierta Atlas AI con un modelo real ni con documentos reales.** Detalle y sesgos en
> [evaluation.md](../evaluation.md).

| Métrica | Sin reranking | Con reranking léxico |
| --- | ---: | ---: |
| Recall de recuperación | 0,813 | 0,931 |
| MRR | 0,599 | 0,979 |
| Respuestas correctas | 0,542 | 0,625 |
| Fidelidad | 1,000 | 1,000 |
| Abstención válida | 0,875 | 0,875 |
| Alucinación | 0,031 | 0,031 |
| Instrucciones inyectadas obedecidas (4 sondas) | 0,000 | 0,000 |

El reranking «mejora» tanto porque el vector de los embeddings falsos es casi ruido y el léxico lo corrige: con un
embedding real la mejora sería menor y podría no existir. Por eso `SEARCH_RERANK` sigue en `off` por defecto.

**Calidad del criterio automático**: la calibración preliminar (12 preguntas, kappa 1,0) la etiquetó Claude viendo el
veredicto automático; **no es una revisión humana independiente** y no demuestra la fiabilidad del criterio. Sigue
pendiente.

Pruebas del software: más de 1 100 tests de backend (con PostgreSQL real), 88 de frontend y 6 E2E con Playwright;
la puerta de regresión pasa con las 10 métricas.

## Costes

- **Ejecutarlo en local: 0 €** de infraestructura.
- **Con OpenAI** (estimación con tarifas públicas, a confirmar): una pregunta cuesta del orden de una milésima de
  dólar o menos (contexto máximo de 3 000 tokens más la respuesta); indexar un PDF típico de 100 páginas, menos de
  0,002 $. Las cuotas (100 preguntas y 300 000 tokens por usuario y día) acotan el gasto en el peor caso.
- **Azure** se estudió y se descartó por coste: ~55–160 $/mes de infraestructura fija
  ([azure-deployment.md](../azure-deployment.md)).

## Decisiones y a cambio de qué

| Decisión | Se gana | Se paga |
| --- | --- | --- |
| pgvector en PostgreSQL | Una sola base con filtros por propietario y transacciones | Menos escala que una base vectorial dedicada |
| Abstenerse sin evidencia | No inventar | Algunas preguntas respondibles quedan sin respuesta |
| Cola de ingestión en PostgreSQL | Sin Redis ni Celery; sobrevive a reinicios | Throughput limitado, un worker |
| Sesiones en servidor + CSRF | Revocables, no accesibles desde JS | Estado en la base y más cuidado con CORS |
| Proveedores `fake` por defecto | Tests y evaluación deterministas y gratuitos | Sus números no valen para un modelo real |
| Ejecutar en local y frontend en Vercel | Sin coste ni cuenta de nube | Sin API pública permanente |

## Limitaciones

- Evaluación con modelos falsos, dataset pequeño y sintético, un dominio y un idioma, un solo anotador.
- Sin OCR: los PDF escaneados no se leen.
- La API no está desplegada públicamente; el frontend de Vercel es un escaparate sin backend.
- Docker Compose no se ha podido ejecutar en el entorno de desarrollo (validado con tests de ficheros); las copias de
  seguridad en modo Compose tampoco. El flujo completo sí se verificó con los procesos fuera de Docker.
- Los E2E y las pruebas de humo no corren en CI.
- Registro sin verificación de email; copias sin cifrar; cookies entre dominios dependientes del navegador.

## Probarla

```bash
cp .env.example .env && docker compose up -d --build
docker compose exec api python -m app.smoke --api-url http://localhost:8000 --origin http://localhost:3000
```

## Publicar la release

La etiqueta y la release de GitHub se crean a mano, **después** de fusionar los PR de esta versión, sobre el commit de
`main` que quieras congelar:

```bash
git tag -a v1.0.0 -m "Atlas AI v1.0.0" && git push origin v1.0.0
gh release create v1.0.0 --title "Atlas AI v1.0.0" --notes-file docs/release-notes/v1.0.0.md
```
